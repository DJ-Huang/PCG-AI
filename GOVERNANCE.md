# Governance

PICG is currently maintained by the repository owner, who is responsible for releases, security decisions, roadmap priorities, and final merge authority.

## Decision process

Routine changes are discussed and reviewed in issues and pull requests. Decisions should be based on reproducible evidence, compatibility impact, maintenance cost, and the project's goal of portable, editable procedural assets.

Changes to the graph schema, serialized pin or property contracts, binary protocols, licensing policy, security boundary, or project governance require explicit maintainer review. Significant decisions should be recorded in documentation or an architecture decision record.

## Contributions

Community contributions are welcome under [CONTRIBUTING.md](CONTRIBUTING.md). The maintainer may request revisions, decline changes that do not fit the project direction, or defer work that cannot be supported safely. Contributors retain credit through Git history and release notes.

## Releases

Releases follow semantic versioning where practical. Before a release, the maintainer verifies repository contracts, native tests, Web checks, applicable Unity behavior, third-party notices, and asset provenance. Security fixes may be released outside the normal roadmap.

As the maintainer group grows, this document will be updated with nomination, voting, and succession rules.
