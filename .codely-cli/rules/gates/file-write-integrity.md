# File write integrity gate

## 问题

在 Windows 工程里用 `Write` / 整文件 `StrReplace` 时，若未回读校验，磁盘文件可能出现**每个逻辑行后多一行空行**（`\r\n\r\n` 或 LF 被加倍），表现为行数约 2×、代码「一行一空行」。同目录正常文件可作对照。

## 写后必做（每次 `Write` 或整文件替换后）

1. **立刻 `Read` 被改文件**，确认无「逐行双倍空行」；行数与改动规模合理。
2. **对照同目录已有文件**的换行密度（缩进、空行习惯一致），勿引入整文件「一行一空行」。
3. 若异常：**当场重写**为正常换行后再结束任务；不得留给用户发现。

## 写时习惯

- 小改动优先 **局部 `StrReplace`**，避免整文件 `Write`。
- `Write` 内容使用**常规单行换行**（逻辑行之间最多一个空行分隔段落）；禁止在源码每行末尾再插空行。
- 批量改多文件时，**每个文件**写后各自 `Read` 抽检，不要只验最后一个。

## 完成前自检

| 检查 | 失败则 |
|------|--------|
| 行数约为预期（非约 2×） | 重写文件 |
| 无「每行后都有空行」模式 | 重写文件 |
| 与邻近平文件排版一致 | 按邻文件修正 |
